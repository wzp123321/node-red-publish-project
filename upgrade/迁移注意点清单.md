## 2. Dashboard 1.0 → 2.0 行为差异（隐性坑）

### 2.1 残留旧节点 ⚠️ 已删除

- **现象**：官方迁移产物中残留 1.0 专用节点：`ui_base`×1（旧根节点）、`ui_spacer`×13/35、`ui_template`×4。
- **风险**：新环境未安装 node-red-dashboard 1.0，这些节点显示为"未知节点"并报错；ui_spacer 无 2.0 对应物。
- **当前状态**：`ui_base`、`ui_spacer` 已全部删除；`ui_template` 已重写为 `ui-template`（见 2.2）。✅
- **回退**：如需还原，`convert.json.bak` 为官方迁移原始产物。

### 2.2 ui-template 内容不兼容 ⚠️ 已重写

官方工具**未转换模板内容**，4 个模板全部需人工重写，当前状态：

| 模板       | 1.0 写法                                           | 2.0 处理                                 | 状态      |
| ---------- | -------------------------------------------------- | ---------------------------------------- | --------- |
| Upload Btn | `scope.send({payload})` + `md-raised md-button` 类 | `v-btn` + `this.send()`                  | ✅ 已重写 |
| heatmap1   | `scope.$watch('msg')` + echarts.setOption          | `onmessage(msg)` 钩子 + 动态加载 echarts | ✅ 已重写 |
| 调用HTML   | `ng-include="/中央空调能效分析.html"`              | iframe 引入                              | ✅ 已重写 |
| 下载链接   | 裸 `<a>` 标签                                      | Vue 模板包裹                             | ✅ 已重写 |

**重写后的注意事项**：

- heatmap1 的 echarts 改为**动态加载** `/echarts.min.js`（2.0 的 Vue SFC 编译不支持模板内直接 `<script src>`）；若资源未部署，图表不显示。
- 调用HTML 从 `ng-include`（内嵌、共享页面样式）改为 **iframe**（独立文档、不共享样式），渲染结果可能有视觉差异；高度固定 800px。
- Upload Btn 发送消息依赖节点的 `allowOutgoingMsgs`（原 `storeOutMessages`）为 true，原接线保持不变。

### 2.3 页面 path ⚠️ 已修复

- **现象**：
  - 重复 path：溧阳 `/下载运行记录`；张家港 `/下载运行记录`、`/手动开关`、`/手动调节` 各重复（1.0 的 tab 无 path 概念可同名，2.0 的 page 必须唯一）。
  - 中文 path：如 `/导入文件`、`/中央空调能效分析报告`，2.0 中 URL 编码后易乱码。
- **当前状态**：已全部改为唯一英文 path（如 `/import-files`、`/download-records`、`/download-records-2`）。✅
- **影响**：所有页面 URL 改变，外部书签/硬编码链接失效，需同步更新。

### 2.4 ui-chart 属性 ⚠️ 已部分修复

- **已确认兼容，无需修改**：`removeOlder`/`removeOlderUnit`/`removeOlderPoints`（2.0 官方流同样使用这些属性）；`ymin/ymax` 字符串（2.0 官方亦为字符串）；`width/height` 字符串（2.0 官方亦为字符串）。
- **已修复**：`legend:"false"`（字符串）→ `showLegend:false`（布尔）；`xformat:"HH:mm:ss"`（moment 语法）→ `xAxisType:"time"` + `xAxisFormat:"%H:%M:%S"`（d3 语法）。✅
- **数据格式风险（关键，未处理）**：
  - 上游喂图表的全部是**单值数字**（`msg.payload = 数值`），2.0 原生兼容（数字 payload + topic 作系列名 + 自动时间戳）。
  - 2.0 图表要求时间戳为 **epoch 毫秒数字**；1.0 接受字符串时间。若未来改造上游为批量数组数据，必须用毫秒时间戳。
  - 已知 2.0 缺陷（v1.30.x）：`{x, y}` 对象格式数组不渲染；单点注入正常。规避：用 `[时间戳, 值]` 数组点或单值注入。

### 2.5 主题体系 ⚠️ 部分丢失

- **现象**：2.0 `ui-theme` 仅支持 5 个色键 `surface/primary/bgPage/groupBg/groupOutline`；1.0 中定制过的其他颜色（如 `group-textColor #1bbfff`、widget 文字/边框/背景色）**在 2.0 无对应配置项，无法迁移**。
- **当前状态**：已对齐 `bgPage #fafafa`、`groupOutline #ffffff`、`primary #0094CE`、`groupBg #ffffff`。✅（可映射部分）
- **遗留**：`group-textColor #1bbfff` 等定制色丢失，视觉有差异，需在 2.0 中用 CSS 覆盖或接受默认。

### 2.6 组件消息格式差异（未处理，需回归验证）

- **ui-button**：点击输出 `payload` + `topic` 兼容；2.0 新增 `emulateClick`、`buttonColor/textColor/iconColor` 等属性已生成。
- **ui-text**：1.0 默认 `{{value}}` 格式 → 2.0 用 `{{msg.payload}}` 模板，转换产物已带 `format:"{{msg.payload}}"`，但**每个 ui-text 需抽查**是否被上游 msg 字段正确填充（1.0 支持 `msg.payload` 之外的其他字段引用，2.0 模板语法同）。
- **ui-dropdown**：options 的 `value/type` 结构兼容；2.0 需要 `options` 中 type 字段（str/num）正确，抽查混型值。
- **ui-slider**：`outs:"end"` 为 1.0 老属性，2.0 已改事件模型，需实测滑动后是否仍按原语义输出（2.0 默认拖动过程也发，若需松手才发要调整）。

### 2.7 ui-date-picker 转换 ⚠️ 已确认

- 2.0 无独立日期选择器，工具转换为 `ui-text-input`（mode: date，含 `delay/sendOnDelay` 属性）。转换合理，但输出格式（时间戳/字符串）与 1.0 可能有差异，需回归。

### 2.8 页面布局（未处理，观察项）

- `ui-group` 的 `width:"32"` 等大宽度值来自 1.0（1.0 允许任意单位宽度），2.0 栅格语义不同，部分组可能布局超宽或换行，需在浏览器实测调整。
